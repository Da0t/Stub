# Path 6 — Mint, Spin & Shelf

**Branch:** `path/6-mint-spin-shelf`
**Mission:** Turn earned presence into an object, reveal it with delight, and put it on a shelf that updates live.

> Project overview: see `README.md` on `main`. Shared types: [docs/CONTRACTS.md](docs/CONTRACTS.md). **Read the contracts before writing code.**

---

## Why this path exists

This is where the product becomes a product, and it is where the Pokémon Go comparison gets won or lost.

Pokémon Go rewards you for **arriving** — the reward is generated by the app, identical for everyone, and exists whether or not you cared about what you walked to. We reward you for **being present**: the card does not exist until you take a photo, and your photo *is* the card face. **Two people at the same set walk away with different objects.** There is nothing to farm, because the artifact is a record rather than a prize.

Every design decision on this path serves that distinction. When you are tempted to add a streak, a leaderboard, or a daily bonus — that is the Pokémon Go gravity well, and it is the one thing that makes a music-industry judge stop listening.

You own step 3 of the build order: *"Mint + spin + shelf — if you stop here, you have a product."*

## Eligibility

All five required:

1. Inside the stage polygon
2. During the set window, **±15 min grace**
3. Dwell **≥ 5 min** inside that window
4. **At least one photo** captured inside the window
5. **No existing card** for this `(user, set)` pair

Condition 4 is the load-bearing one. It is what makes the card a record of presence rather than a prize for arriving, and it is why your photo is the card face. Never relax it.

Import the 5-minute threshold from `lib/dwell/thresholds.ts`. Do not retype the constant.

## The spin

**The card is already earned by the time the spin appears. The spin is not a lottery for whether you get it — it reveals which frame variant you got. Delight without deception.**

This distinction is worth protecting in code and in copy. Nothing in the spin UI may suggest the user might come away empty-handed. No "better luck next time," no near-miss animation, no rarity slot machine that lands one notch short.

```
LOCKED       → conditions unmet
AVAILABLE    → all conditions met, unspun
SPINNING     → animation, ~1.5s
MINTED       → card on shelf, immutable
```

**`AVAILABLE` persists.** If you leave without spinning, the card waits — no punishing someone for keeping their phone in their pocket, which is the behaviour we actually want to encourage. Persist unspun availability in `pendingMints` (path 1's store) *and* server-side.

`MINTED` is immutable. A card never changes variant, photo, or rarity after minting.

### Animation
~1.5 seconds, one beat, then the card lands. Resist a long reveal — you will watch it fifty times today and judges will watch it twice. Make it feel physical: a flip, a settle, a small weight. `prefers-reduced-motion` cuts straight to the result.

## Frame variants

| Variant | Look | Bias |
|---|---|---|
| `ranger_badge` | Park signage. Heavy serif, forest green + cream, engraved artist/stage. | Default. Headliners. |
| `trail_marker` | Vertical wooden sign, stacked names, arrows and distances. | Small stages. |
| `fog_layer` | Karl the Fog wash. Intensity scales with set time. | Evening and night sets. |
| `disco_bison` | The joke card. Real bison in the park, disco ball in their collage. | Random low-probability across all sets. |
| `field_notes` | Kraft paper, handwritten annotation, taped polaroid. | Reserved for the Wrapped summary page. |

**Selection is contextual, weighted — not uniform random.** Sketch of the policy:

```
base weights:
  ranger_badge  0.45   ×2.0 if isHeadliner
  trail_marker  0.30   ×2.0 if estimatedAudience is small
  fog_layer     0.20   ×2.5 if set starts after 7PM
  disco_bison   0.05   flat, never boosted, never suppressed
  field_notes   0       (Wrapped summary only — never minted for a set)
```

**Every set of frames needs one stupid card, because that is the one people post.** `disco_bison` is that card. Do not make it earnable, do not make it rare-because-valuable, do not gate it behind anything. It is a 5% joke and it is doing real work — the ranger-and-bison theme is the festival's own 2026 art program identity ("Bison and Ranger Ruth"), not our invention.

`seed` makes selection deterministic per `(userId, setId)` so a re-render never changes an existing card. Hash the seed; do not call `Math.random()`.

## Rarity is looked up, never assigned

**Invented tiers are the fastest way to make this feel cheap.** Derive it:

```
rarityScore = f(
  estimatedAudience (inverse),   // 300-person Duboce set > headliner
  isFestivalDebut,               // JamBase knows
  isFinalShow,                   // JamBase knows
  hasSurpriseGuest,              // setlist data
  concurrentHeadlinerRunning     // you skipped a headliner for this
)
```

A card from a small stage is **genuinely rarer** than a Lands End card, because fewer people were standing there. That is true, checkable, and much more satisfying than a colour-coded tier someone made up.

Implementation notes:
- Normalise `estimatedAudience` inversely across the event's range. If path 3 reports it as `null`, drop the term and renormalise — do not substitute a default, which would silently score every set identically.
- `concurrentHeadlinerRunning` comes from path 5's per-set skipped data. This term is the one that ties rarity back to opportunity cost, so keep it.
- Output `0..1`. Path 7 draws a rarity mark only above `0.7`.
- **No tier names.** No "legendary." If you must label, label with the fact: *"one of ~300 people there."*

### Theme packs travel
Outside Lands cards wear ranger-and-bison. A different festival wears its own pack. The collection becomes visually legible at a glance — you can tell someone has been to six festivals by looking at the shelf. Keep `themePack` threaded through `CardRenderInput` even though today there is only one.

## Acceptance criteria

1. All five eligibility conditions each independently block a mint when unmet.
2. `AVAILABLE` survives a full page reload and an app restart.
3. Spinning twice for the same set produces exactly one card.
4. Two users minting the same set get **visibly different cards** — different photo, and often a different frame.
5. A small-stage set scores higher rarity than a headliner set with the same dwell.
6. Frame selection is stable: re-rendering an existing card never changes its variant.
7. The shelf updates live on a second device with no refresh.

## Gotchas

- Do not add streaks, leaderboards, daily bonuses, or combo multipliers. Every one of them converts this into the product we are positioning against.
- `Math.random()` in variant selection will make cards change on re-render and will make the demo look broken. Seed it.
- Optimistic mint + server dedupe can race into a duplicate tile. Key the shelf list by `setId`, not by array index.
- The spin sheet must not block a subsequent capture. Users take photos in bursts; the sheet must be dismissible instantly.
- If `estimatedAudience` is null across the board (path 3 may not get it), rarity collapses to a constant. Detect that and fall back to `concurrentHeadlinerRunning` + `isHeadliner` inverse, rather than shipping a field that is always 0.5.
- Never mint `field_notes` for a set. It is reserved for the Wrapped summary page (path 8).
